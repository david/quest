# Goal Clarification

Use this guide when desired outcomes, priorities, scope, or success expectations
are materially unclear or disputed. Creating a quest does not require a separate
goal conversation when the user has already supplied clear intent.

Read the relevant goal context and existing evidence. Build on supplied answers;
do not run a fixed questionnaire or ask the user to repeat settled facts.

Clarify only what could change the work:

- Who benefits, and what should improve for them?
- What observable result would count as success?
- Which outcomes matter most if priorities conflict?
- What constraints are fixed, and what is out of scope?
- Which uncertainty could change the goal or make it unnecessary?

Distinguish desired outcomes from proposed solutions. For example, a dashboard
is a solution; the goal may be helping someone decide which requests need action.
Preserve a solution the user explicitly requires as a constraint.

Ask the user about intent, priorities, and consequential choices evidence cannot
settle. Investigate factual gaps within the authorized scope. Leave ordinary
implementation choices to planning or execution. Use concrete examples to explain
tradeoffs and distinguish observations from assumptions.

Summarize new or materially changed interpretations and seek confirmation when
they affect the work. Clear supplied intent or confirmation during discussion is
sufficient; do not require another approval round. Stop when the goal is clear
enough to act on, rather than exploring every design branch.

Keep confirmed intent distinct from proposals and unresolved questions. Apply
quest's shared update contract when goals change, including affected plans and
tasks. Clarifying a goal neither achieves it nor authorizes implementation. Keep
the next useful question or action recoverable if clarification pauses.
